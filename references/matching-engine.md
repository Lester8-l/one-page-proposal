# 需求匹配引擎

一頁紙方案的成敗，在於「客戶關注」那一欄能不能讓客戶心想「係喎，我正是擔心這個」。
所以第一步不是挑產品，是**翻譯客戶的話**。

## 一、三層翻譯：原話 → 風險 → 產品

客戶從來不會說「我需要轉移收入中斷風險」。他說的是「唔想病咗拖累屋企」。
你的工作是往下挖兩層：

```
客戶原話（表層）          底層風險                對應險種
「醫療費好貴」      →   大額醫療開支侵蝕資產   →   醫療險
「唔想病咗冇收入」  →   患病期間收入中斷       →   危疾險
「想啲錢唔好縮水」  →   現金購買力被通脹蠶食   →   儲蓄險
「我走咗屋企點算」  →   家庭經濟支柱缺口       →   人壽險
「驚整親做唔到嘢」  →   突發失能／被動收入斷   →   意外險
```

**寫進方案卡時，左欄一律用客戶的原話（改寫成書面也保留他的語氣），
右欄才出現產品與數字。**順序不能反——先產品後需求，客戶會覺得你在賣東西。

## 二、問出真需求的提問路徑

如果用戶只給了一個模糊背景（例如「40 歲，有兩個小朋友」），用這四問補齊，
**一次只問一問，不要連珠炮**（Lester 的習慣）：

1. **最擔心咩事？** → 抓主要風險（通常客戶第一個講的就是最痛那個）
2. **而家有咩保障？公司／自己買咗咩？** → 找缺口（有醫保沒危疾？有危疾沒人壽？）
3. **如果聽日發生，你手上有幾多現金可以頂幾個月？** → 量化缺口，決定保額級數
4. **每個月大概可以撥幾多出嚟？** → 決定方案的可負擔性（**先講需求再講錢，順序反了會變推銷**）

問完，你手上應該有：**1–3 個關注 + 1 個保障缺口 + 1 個預算區間**。
夠寫一頁紙了。

## 三、多需求疊加：主險 + 附加保障

一個客戶常常同時有兩三個關注。**不要在一頁紙塞三個產品**（塞不下、客戶也記不住）。

做法是選一個**主險**當方案名，其餘需求用**附加保障（rider）**或「方案已包含」的方式帶過：

```
方案：XX 危疾保障計劃（主險）
  ├ 危疾一筆過賠償      → 回應「病咗冇收入」
  ├ 附加住院醫療保障     → 回應「唔想動用積蓄」
  └ 附加身故保障        → 回應「屋企人點算」
```

這樣三條關注落在同一個方案下，客戶會覺得「一個方案解決晒」，而不是「你要我買三樣嘢」。
如果預算只夠主險，就在文字稿標明「附加保障為選項，可日後加保」，不要硬塞。

## 四、賣點句的寫法公式

每一條方案要點都用同一個句式：

```
〔產品事實／數字〕　→　〔所以對你嘅意義〕
```

| ❌ 差 | ✅ 好 |
|---|---|
| 危疾保障 HK$100 萬 | 確診即賠 HK$100 萬　→　補住大約 2 年收入缺口 |
| 住院實報實銷 | 醫療開支實報實銷　→　唔使動用你嘅積蓄 |
| 儲蓄保單有現金價值 | 第 10 年預期現金價值約 HK$XX 萬　→　可作小朋友升學儲備〔非保證〕 |

三個要點檢查：
1. **有數字嗎？** 沒有數字的賣點是形容詞，客戶記不住。
2. **「→」後面講的是客戶，不是產品嗎？** 講產品功能的都要改寫。
3. **三條之間是否重複？** 三條都講「有保障」等於只講了一條，要分別對應不同關注。

## 五、常見誤配

| 客戶說 | 表面像 | 實際常是 | 提醒 |
|---|---|---|---|
| 「我想儲錢」 | 儲蓄險 | 教育基金／退休／首期 | 問清**用途與年期**，年期對不上就不要推儲蓄險 |
| 「公司有醫保啦」 | 唔需要醫療險 | 醫保多數不包危疾一筆過賠償 | 指出**保障類型不同**，不是重複 |
| 「我後生唔急」 | 意外險 | 保費隨年齡升，年輕反而便宜 | 用「同樣保額，而家買平過 10 年後買」切入 |
| 「等我諗下先」 | 唔想買 | 通常是有具體疑慮未講 | 追問「有咩令你未決定？」不要當場逼 |

## 六、方案卡的邏輯自檢（出稿前跑一次）

- [ ] 客戶關注 3 條，全部是**客戶會講的話**，不是產品語言
- [ ] 方案要點每一條都有 `→`，且箭頭後說的是客戶得到的東西
- [ ] 三條要點分別回應三個關注，**沒有一對多或漏掉**
- [ ] 每個數字有單位、有「約」字（除非是保單確定的保證數字）
- [ ] 數字條上的保費**在客戶預算內**（否則要同時提出調整選項）
- [ ] 下一步是**具體動作**（約 30 分鐘對條款），不是「歡迎查詢」
- [ ] 全文掃過合規禁詞（跑 `check-compliance.py`）
